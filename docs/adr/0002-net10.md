# ADR 0002: Plataforma .NET 10

- Estado: Aceptado
- Fecha: 2026-10-11

## Contexto

El proyecto es nuevo y necesita una versión de .NET con soporte largo. .NET 10 es una versión LTS con soporte hasta el 2028-11-14. .NET 8, también instalado en la máquina de desarrollo, sale de soporte el 2026-11-10, es decir, en cuestión de semanas desde el inicio del proyecto.

## Decisión

- Todos los proyectos apuntan a `net10.0` (el `TargetFramework` se declara en cada `.csproj` y una prueba de convenciones lo comprueba).
- `global.json` fija el SDK `10.0.302` con `"rollForward": "latestFeature"` y `"allowPrerelease": false`. Permite bandas de funcionalidad posteriores (por ejemplo, la imagen `mcr.microsoft.com/dotnet/sdk:10.0` trae 10.0.401) sin aceptar versiones preliminares.
- La imagen de ejecución es `mcr.microsoft.com/dotnet/aspnet:10.0-alpine`.

## Consecuencias

- Hace falta el SDK 10 en la máquina de cada persona y en la integración continua (`actions/setup-dotnet` lo lee de `global.json`).
- Hay soporte hasta noviembre de 2028 sin migrar de plataforma.
- Si el SDK local es anterior a 10.0.302, los comandos `dotnet` fallan con un mensaje claro en lugar de compilar con otra versión.

## Alternativas

- **net8.0:** el soporte termina en 2026-11-10; nacería casi sin vida útil.
- **Multi-target (net8.0 y net10.0):** duplica la matriz de pruebas y limita las APIs disponibles sin aportar nada a una aplicación que se despliega, no se distribuye como biblioteca.
- **Sin `global.json`:** cada máquina usaría un SDK distinto y la compilación dejaría de ser reproducible.
